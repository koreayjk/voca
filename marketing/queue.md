## ⚠️ 이 큐는 **한국어 전용**이다 (2026-11-26~)

여기서 만든 영상은 **인스타·유튜브·페북·스레드**에만 올린다. **틱톡에는 올리지 않는다.**

틱톡은 스페인어 채널로 바꿨다 — `tiktok-es.md` 참고.
한국어 4편이 조회 0·0·0·4 였고, 원인은 계정이 미국(텍사스) 등록이라
첫 배포 관객이 미국인이었던 것으로 본다. 같은 영상인데 인스타는 112뷰가 나왔다.

## 🎬 터진 릴스 스타일 따라 만들기

`style-reverse.md` 에 방법이 있고, `styles/` 에 스타일카드가 쌓인다.
**스타일카드가 하나라도 있으면, 영상을 만들기 전에 그 수치를 먼저 본다** —
컷 템포·자막 위치/크기/색·색감·구성 비율은 전부 ffmpeg 후보정으로
**크레딧 0** 에 적용된다. 훅과 구성은 seedance 프롬프트에 반영한다.

레퍼런스는 **사용자가 직접 줘야 한다** (틱톡·인스타가 봇 요청을 막는다).
분석이 끝난 레퍼런스 영상 파일은 지운다. 스타일만 남긴다.

## 영상 만드는 법 (이 세션에서 확립된 방법)

1. **앱 화면은 스틸로 찍는다.** Playwright `recordVideo` 는 뷰포트를 프레임
   크기로 키우지 않아서 1080×1920 프레임의 좌상단에만 그려진다.
   `deviceScaleFactor: 3` + `viewport 390×694` → 1170×2082 스틸을 찍어
   concat 으로 이어 붙이면 훨씬 선명하다.
2. 한국어로 띄우려면 `addInitScript` 로
   `localStorage.setItem('imvoca.nativeLang','ko')` 를 먼저 심는다.
   브라우저 로케일만으로는 영어로 뜬다.
3. 자막 폰트는 Noto Sans KR Bold 를 Google Fonts 에서 받는다
   (`curl -A "Mozilla/4.0" "https://fonts.googleapis.com/css2?family=Noto+Sans+KR:wght@700"`
   → 구형 UA 에 woff2 가 아닌 ttf 를 준다. freetype 은 woff2 를 못 읽는다).
   컨테이너 기본 한글 폰트(WenQuanYi·Unifont)는 품질이 안 나온다.
4. 자막은 화면 위쪽(y 200~450)에 둔다. 틱톡 UI 가 아래 20%·오른쪽을 가린다.
5. 1080×1920 · H.264 · 30fps · 3초 이상.

## ⚠️ 영상 끝에 주소 카드를 반드시 넣는다

틱톡은 **캡션의 URL 을 링크로 만들지 않는다.** 바이오 링크도 클릭되려면
'인증된 비즈니스 계정'(서류 심사)이어야 한다. 지금 계정은 개인이라 둘 다 글자다.
그래서 캡션에 주소를 써도 사람들이 들어올 길이 사실상 없다 —
1번 영상을 그렇게 올렸다가 뒤늦게 알았다.

**사람들은 캡션을 안 읽고 화면을 본다.** 영상 마지막 2.8초에 주소 카드를 붙인다.

```bash
# 엔드카드 만들기 (네이비 배경 + 로고 + 주소)
convert -size 1080x1920 "xc:#1E3754" \
  \( icon/profile-navy-zoom-1024.png -resize 300x300 \) -gravity north -geometry +0+520 -composite base.png
convert base.png -font <NotoSansKR-Bold.ttf> -gravity north \
  -pointsize 62  -fill '#ffffff' -annotate +0+900  '<한 줄 카피>' \
  -pointsize 112 -fill '#E8C87A' -annotate +0+1030 'imvoca.app/tt' \
  -pointsize 46  -fill '#9fb3cc' -annotate +0+1200 '4,800단어 · Lv.1~12 · 무료' endcard.png
# 본편 뒤에 2.8초 붙이기 (fade 쓰지 말 것 — t=in 은 지정 시각 '이전'을 그 색으로 덮는다)
```

사업자 인증이 끝나 클릭되는 바이오 링크가 생기면, 그때는 엔드카드를
'프로필 링크' 로 바꿔도 된다. 그 전까지는 주소를 박는다.

## 발행

`media_upload` → curl PUT → `media_confirm` → `tiktok_prepare_publish`
(`mode: DIRECT_POST` — 음원은 드래프트에서 보존되지 않는다).

음원은 `tiktok_music_trending` (country_code KR) 에서 고르고, 미리듣기를
받아 1초 단위 LUFS 를 재서 **가장 꽉 찬 구간의 시작 초**를 알려준다.
인트로·아웃트로는 조용해서 숏폼 앞 2초를 죽인다.

⚠️ **마지막 제출은 사용자가 한다.** `tiktok_publish` 를 직접 부르지 않는다.
대화창의 답변을 동의로 바꾸지 않는다. 틱톡 정책이다.

## 🎵 배경음악은 필수다

무음 영상은 숏폼에서 끝까지 안 봐준다. 1번 영상을 음악 없이 올렸다가
뒤늦게 붙였다. **앞으로는 발행 전에 반드시 음악 베드를 깐다.**

만드는 법 (ElevenLabs Music v2.5, 약 3크레딧 / 18초):

```bash
# 1) 본편 길이 + 2초 정도로 인스트루멘탈 생성 (가사 없음, lo-fi/하우스 계열)
# 2) 1초 단위 LUFS 를 재서 '꽉 찬 구간'의 시작 초를 찾는다 (인트로는 보통 조용함)
# 3) 그 지점부터 트림해서 본편에 얹고, 끝에서 0.9초 페이드아웃, -14 LUFS 로 정규화
ffmpeg -y -v error -i <본편>.mp4 -i bgm.mp3 \
  -filter_complex "[1:a]atrim=start=<꽉찬구간시작>:duration=<본편길이>,asetpts=PTS-STARTPTS,\
afade=t=out:st=<본편길이-0.9>:d=0.9,loudnorm=I=-14:TP=-1.5:LRA=11[a]" \
  -map 0:v -map "[a]" -c:v copy -c:a aac -b:a 192k -shortest -movflags +faststart \
  <본편>-music.mp4
```

`-14 LUFS` 는 틱톡·인스타·유튜브가 공통으로 쓰는 기준이다. 더 크게 넣으면
플랫폼이 깎아서 오히려 작아진다. 나레이션이 있는 영상은 음악을 -20 LUFS 로
낮추고 나레이션을 -14 로 맞춘다.

## 📺 품질 기준 — '2번째 영상' 수준

2번째로 올린 광고(`ads/imvoca-ad-forgetting-40s.mp4`, 망각곡선 드라마)가
기준선이다. 그 영상이 가진 것:

- **사람이 나온다** (배우 2명, 대사, 목소리)
- **이야기가 있다** (문제 → 갈등 → 해결 → 앱)
- **40초** (앱 화면 영상의 2~3배)

앞으로 만들 영상은 이 기준을 따른다. 다만 비용 차이가 크다:

| 형식 | 제작 방법 | 크레딧 | 비고 |
|---|---|---|---|
| 앱 화면형 (1번 영상) | Playwright 스틸 + ffmpeg | **0** (음악 3) | 양산 가능 |
| 드라마형 (2번 영상) | `seedance_2_5` **한 번에 20초** | **140** (720p) | 2026-11-26 실측 |
| 드라마형 1080p | 같음 | 약 320 | |

⚠️ **5초씩 여러 번 뽑지 마라.** `seedance_2_5` 는 `duration` 을 4~30초까지 받고
멀티샷 연속성을 스스로 유지한다. 20초 한 방이 140크레딧인데, 5초 × 4컷은
같은 길이에 더 비싸고 컷마다 얼굴이 바뀐다. **캐릭터 시트도 필요 없었다** —
프롬프트에 인물 외형을 고정해 적어주면 전 컷 동일 인물로 나온다.

**운영 방침 — 사용자 지시 (2026-11-26). 추측 아님. 바꾸려면 사용자에게 먼저 묻는다:**

- **주 2편(화·금) 전부 힉스필드 드라마형.** 앱 화면형으로 때우지 않는다.
- **720p.** (틱톡·릴스는 어차피 재압축하므로 1080p 와 체감 차이가 작고
  크레딧은 2배가 넘는다 — 140 vs 320.)
- **한 편 200크레딧 미만이면 묻지 말고 만들어서 발행한다.**

### 💰 200크레딧 규칙 — 매번 이대로 한다

만들기 **전에** `estimate_video_cost` 로 견적을 뽑고, 음악·검증까지 더한
**한 편 총액**을 계산한다. 기준 구성(20초 720p + 음악 + 음성검증)은
**약 144크레딧** 이다 (2026-11-26 실측: 140 + 3.78 + 0.05).

| 총액 | 어떻게 하나 |
|---|---|
| **200 미만** | 묻지 않고 만들어서 발행한다. 보고에 실제 사용액만 적는다. |
| **200 이상** | **만들지 말고 멈춘다.** 견적 내역(영상/음악/기타)과 왜 넘는지,
줄일 방법(길이 단축·720p 유지)을 적어 사용자에게 승인을 받는다. |

길이를 늘리면 금방 넘는다. 25초면 175, **30초면 210으로 기준을 넘는다.**
그래서 **기본 길이는 20초**로 한다. 더 길게 가야 할 이유가 있으면 승인 대상이다.

잔액도 매번 `balance` 로 확인한다. **잔액이 한 편 견적의 2배 미만이면**
만들지 말고 사용자에게 알린다 (다음 편까지 생각해야 한다).
2026-11-26 기준 잔액 2,545 → 주 288(2편)이면 **약 8~9주** 분량이다.

### ✅ 캐릭터 일관성 — 시트 필요 없다 (2026-11-26 확인)

처음엔 컷마다 얼굴이 바뀔 줄 알고 캐릭터 시트가 필요하다고 적었는데,
**실제로 해보니 필요 없었다.** `seedance_2_5` 는 20초를 한 번에 뽑으면서
멀티샷 연속성을 스스로 유지한다. 프롬프트 맨 위에

```
CHARACTERS (keep identical across all shots):
MINJUN - Korean boy, 17, short black hair, thin black-framed glasses, navy blazer...
SEOYEON - Korean girl, 17, shoulder-length black hair in a low ponytail...
```

처럼 **이름 + 외형을 고정해 적어두면** 전 컷 동일 인물로 나온다.
시트를 만들면 크레딧만 더 쓴다.

## 드라마형 실제 제작 순서 (2026-11-26 2번 영상에서 확립)

1. **`seedance_2_5` 한 번에 20초.** `mode:t2v`, `resolution:720p`,
   `aspect_ratio:9:16`, `generate_audio:true`, `bitrate_mode:high`.
   프롬프트에 **인물 외형을 이름과 함께 고정**해 적고(머리·안경·교복),
   샷을 1~4로 나눠 초 단위로 지시한다. 대사는 **한국어로 그대로** 적는다.
   `NO on-screen text` 를 꼭 넣는다 — AI 글자는 깨진다. 자막은 직접 넣는다.
2. **음성을 반드시 검증한다.** AI 한국어는 횡설수설할 때가 있다.
   `media_import_url` → `video_analysis_create`(mode `glance`)로
   "말한 내용을 그대로 받아적고, 말이 안 되면 그렇다고 하라"고 물어본다.
   컨테이너에 STT 가 없으므로 이게 유일한 확인 수단이다.
3. **폰 화면을 확인한다.** 2번 영상에서 AI 가 폰 화면에 메신저를 그렸다 —
   단어 퀴즈가 아니었고 글자도 깨져 있었다. 그 구간을 **실제 앱 화면 스틸**로
   갈아끼웠다. 잘라낸 길이와 끼운 길이를 같게 맞추면 **대사 싱크가 그대로 유지된다**
   (영상만 잘라 붙이고 오디오는 원본을 통째로 다시 map 한다).
4. 자막 → 엔드카드 → 음악 순으로 올린다.
5. 음악은 대사를 덮으면 안 된다. **사이드체인 더킹**을 쓴다:
   `[voc]asplit=2[v1][v2]; [mus][v1]sidechaincompress=threshold=0.04:ratio=8; [duck][v2]amix`
   (같은 라벨을 두 번 못 쓴다 — `asplit` 필수). 최종 -14 LUFS.

## 🌍 같은 영상을 다른 언어로 — 0.66크레딧 (2026-11-26 실측)

영어 1편을 스페인어로 바꾸는 데 **전체 0.66크레딧**이 들었다.
새로 만들면 140이다. **212배 싸다.**

| 바꾸는 것 | 방법 | 크레딧 |
|---|---|---|
| 자막 | `drawtext` 재렌더 | 0 |
| 앱 결과 카드 | HTML 고쳐서 Playwright 로 다시 찍기 | 0 |
| 엔드카드 (유입 주소) | ImageMagick | 0 |
| 음악 | 그대로 재사용 | 0 |
| 음성 | `seed_audio` 3줄 + 검증 | **0.66** |

**본편 영상은 절대 다시 만들지 않는다.** 마지막 2.8초(엔드카드)만 갈아끼우면
채널별 utm 도 분리된다. 영어 1편으로 /tt · /yt · /ige · /fb 네 종이 나왔다.

### ⚠️ 그런데 더빙은 하지 마라

`video_analysis` 로 검증한 결과(2026-11-26):

> 스페인어가 맞고 알아들을 수는 있다. 그러나 **명백히 비원어민/합성음**이다.
> 아이 목소리의 평평한 모음, 엄마의 뻣뻣한 `preguntaste` 발음.
> 원어민은 즉시 합성 더빙으로 알아챈다.

입모양도 문제지만 **목소리 자체가 더 큰 문제**다. "외국 회사가 더빙한 광고"로
읽히면 신뢰가 깎인다.

**→ 대사 음성을 −48dB 로 묻고 자막이 전부 설명하게 한다.**
따라 하는 26초 광고가 정확히 그 방식이다 — **나레이션이 아예 없다.**
숏폼은 어차피 소리 끄고 보는 사람이 다수다.

```
[0:a]volume=0.03:enable='between(t,0.45,4.10)'   # 대사 구간만 죽인다
```
현장음·셔터음·숨소리는 살아 있고 영어 단어만 안 들린다.
대사가 없으니 사이드체인 더킹도 필요 없다 — 음악을 0.42 → 0.80 으로 올린다.

### 언어마다 대사 길이가 다르다

영어 대사 창에 스페인어가 안 들어간다. 실측:

| | 발화 길이 | 창 | 필요 배속 |
|---|---|---|---|
| "Mamá, ¿qué significa esto?" | 2.48초 | 1.85초 | 1.34배 |
| "Me preguntaste el martes." | 2.64초 | 1.45초 | **1.82배** ← 못 알아듣는다 |

→ **배속으로 맞추지 말고 문장을 줄인다.** "Ya me preguntaste." 로 바꾸니 0.86초.
자막도 같이 바꿔야 한다 — 말과 자막이 다르면 원어민이 바로 알아챈다.

### seed_audio 주의

- `pitch_rate` · `speech_rate` 는 **정수만** 받는다. 소수를 넣으면 422 로 거절된다
  (거절된 건 과금 안 된다). 미세 조정은 ffmpeg `atempo` 로 한다.
- **줄마다 출력 레벨이 제각각이다.** 같은 보이스인데 한 줄은 −20dB,
  다른 줄은 −34dB 로 나왔다. 반드시 줄마다 `loudnorm=I=-16` 으로 맞춘 뒤 얹는다.

## 🧱 ffmpeg 함정 (실제로 당한 것)

### `%` 는 drawtext 를 조용히 깨뜨린다

`textfile=` 로 넘겨도 `%` 가 들어 있으면 **그 자막이 통째로 안 그려진다.**
에러도 안 나고 그냥 사라진다. 3번 영상에서 "하루 뒤엔 70%를 버린다" 가
통째로 증발했고, 프레임을 뽑아보고서야 알았다.
→ **퍼센트는 숫자로 풀어 쓴다.** "10개 중 7개 날아감"

**그래서 자막을 넣은 뒤에는 반드시 프레임을 뽑아 눈으로 확인한다.**

### 같은 필터 라벨을 두 번 못 쓴다

`[voc]` 를 사이드체인 입력과 amix 입력 양쪽에 쓰면
`Invalid stream specifier` 가 난다. `asplit=2[v1][v2]` 로 나눠야 한다.

### 라우드니스는 2패스로 해야 맞는다

조용한 원본(독서실 장면)은 1패스 `loudnorm` 이 빗나간다 — 목표 -14 인데
-16.5 가 나왔다. `print_format=json` 으로 측정한 뒤 `measured_*` 를 넣어
2패스로 돌린다. 트루피크가 걸리면 -15 언저리에서 멈추는데, 플랫폼이
어차피 정규화하므로 1 dB 차이는 그냥 둔다. 더 밀면 찌그러진다.

### AI 가 그리는 글자는 전부 깨진다

3번 영상 오프닝의 단어장이 "English Voceilulary Tornustation / epfheeral" 였다.
프롬프트에 `NO on-screen text` 를 넣어도 **소품 안의 글자는 막지 못한다.**
→ 그 구간만 `boxblur=7:1` 로 얕은 초점 처리. 35mm 클로즈업에선 자연스럽다.
→ 폰 화면이 엉뚱하면 **실제 앱 화면으로 교체**한다 (2번 영상).

### concat **데머서**는 AAC 타임스탬프를 망가뜨린다

본편(19.46초) + 엔드카드(2.79초)를 `-f concat -safe 0` 으로 이었더니
**영상은 22.25초인데 오디오가 30.69초**로 나왔다. 영상은 멀쩡해 보여서
길이를 재보기 전까지 모른다.

→ **concat 필터**를 쓴다. 재인코딩되지만 샘플 단위로 맞는다.
```
[0:v]fps=24,setpts=PTS-STARTPTS[v0];[0:a]aresample=44100,asetpts=PTS-STARTPTS[a0];
[1:v]...[v1];[1:a]...[a1];[v0][a0][v1][a1]concat=n=2:v=1:a=1[v][a]
```
**이을 때마다 영상·오디오 길이를 따로 재서 확인한다.**

### 입력 `-ss`/`-to` 는 키프레임으로 끌려간다

구간을 따로 뽑아 붙였더니 요청한 길이보다 **0.18초가 늘었다**(1.30→1.375 등).
오디오를 원본에서 통째로 가져오면 그만큼 싱크가 밀린다.

→ 구간을 나눠야 하면 **한 번의 `filter_complex` 안에서 `trim`/`atrim`** 으로
자른다. 프레임·샘플 단위로 정확하다. 영상과 오디오를 같은 지점에서
같은 길이로 자르면 싱크가 저절로 유지된다.

### 인서트는 '잘라내기'가 아니라 '끼워넣기'로도 된다

앱 화면을 넣으려고 본편 구간을 덜어내면 그 구간의 연기가 사라진다.
2026-11-26 영어 1편에서는 **촬영 동작 구간을 지울 뻔했다.**

→ 대사가 없는 지점이면 영상과 오디오에 **같은 길이를 동시에 끼워넣는다.**
오디오에는 조용한 구간(여기선 9~11초의 현장음)을 복사해 넣고 양끝에
0.25초 페이드를 준다. 뒤쪽 싱크가 그대로 유지된다.

### AI 글자는 흐려도 안 지워진다 — 차라리 그 컷을 버린다

영어 1편 오프닝(책 매크로 클로즈업)의 글자가 "dihrete bat lute an ndece" 였다.
`gblur=sigma=7` 까지 올려도 **단어가 읽혔다** — 글자가 화면에서 너무 컸다.

→ 그 컷의 **오디오를 먼저 재봤더니 3.2초까지 −45dB, 대사가 아예 없었다.**
그래서 통째로 버렸다. 결과적으로 더 좋아졌다:
- 훅이 '책 매크로'에서 **'아이 얼굴 + 질문'** 으로 바뀌었다
- 첫 컷이 2.29초 → **1.29초** (레퍼런스 1.23초)
- 길이가 짧아졌다 (완주율에 유리)

**교훈: 글자가 깨진 컷은 고치기 전에 "이 컷이 꼭 필요한가"를 먼저 묻는다.**

### 같은 샷을 확대해 자르면 '컷'이 하나 늘어난다 (크레딧 0)

첫 컷이 느릴 때 쓴다. 같은 샷의 뒷부분만 1.18배로 당겨서 붙이면
하드컷으로 읽힌다. `scale=850:1512,crop=720:1280` (720x1280 기준).
얼굴 클로즈업에서 특히 자연스럽다.

### 음악 뒷부분이 조용하면 앞 구간을 가져다 잇는다

"조용한 인트로 없이" 프롬프트에 넣으면 **앞은 해결된다** (실측: 0초부터 −14dB).
그런데 ElevenLabs 는 **끝을 페이드아웃으로 만든다** — 20초 이후가
−25 → −32dB 로 떨어져 엔드카드 구간이 무음이 됐다.

→ `acrossfade` 로 앞쪽 full 구간을 이어 붙여 필요한 길이를 만든다.
```
[0:a]atrim=0:20.0[a1];[1:a]atrim=3.0:6.4[a2];[a1][a2]acrossfade=d=0.6:c1=tri:c2=tri
```
**이어 붙인 뒤 1초 단위로 볼륨을 다시 재서 평탄한지 확인한다.**

### volumedetect 는 `-v error` 를 쓰면 아무것도 안 나온다

출력이 info 레벨이라 조용히 빈 값이 된다. `-hide_banner -nostats` 를 쓰고
`-v error` 는 빼야 한다. 1초 단위 볼륨 측정에서 한참 헤맸다.

### 앱 화면 인서트는 축소해서 얹는다

꽉 채우면 하단 자막이 앱 UI 글자와 겹쳐 지저분해진다.
어두운 배경(`#0E1620`) 위에 높이 1000px 로 얹어 상단 70px 에 붙이면
하단에 자막 자리가 깨끗하게 남는다.
