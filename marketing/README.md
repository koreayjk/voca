## 10. 틱톡 연동 (2026-11-25 연결됨)

힉스필드 MCP 를 통해 연결했다. `connector_id` 는 힉스필드 쪽에 있고,
`tiktok_accounts` 로 상태를 확인한다.

**제가 할 수 있는 것**: 영상 제작 → 힉스필드 업로드 → 캡션·해시태그·설정 준비
**제가 못 하는 것**: 마지막 발행 버튼. 틱톡 정책상 사용자가 위젯에서 직접 제출한다.

영상은 반드시 힉스필드에 업로드돼 있어야 한다(틱톡이 검증된 출처 도메인만 받는다).
`media_upload` → curl PUT → `media_confirm` → 그 URL 로 `tiktok_prepare_publish`.

### 영상 규격 (틱톡)

MP4/WebM/MOV · 1GB 이하 · 3~600초 · 양변 360px 이상 · 23~60fps
사진은 JPEG/WebP 만 (PNG 는 거부됨)

### 만든 영상

`tiktok-01-leveltest.mp4` — 13.8초 · 1080×1920 · 30fps
  0.0~2.2초  AI 훅 (야간 책상, 막막한 학생) + "단어장 200쪽 / 어디부터 외워?"
  2.2~7.8초  실제 레벨 테스트 7문항 + "1분이면 내 레벨 나온다"
  7.8~13.8초 "Lv.8 / 7단어를 물어본 결과예요" + "너는 몇 레벨? / 댓글에 남겨봐"

⚠️ **AI 생성 고지 필요.** 앞 2.2초가 AI 영상이라 `is_aigc: true` 로 표시했다.
AI 소재를 섞은 영상은 항상 켜야 한다.

⚠️ **소리가 없다.** 무음 영상은 틱톡에서 잘 안 퍼진다. 드래프트로 올려서
틱톡 앱에서 유행 음원을 입히는 쪽을 권한다.

### 화면 녹화 소재를 다시 뽑을 때

Playwright `recordVideo` 는 뷰포트를 프레임 크기로 키우지 않는다 —
390×694 뷰포트로 녹화하면 1080×1920 프레임의 좌상단에만 그려지고 나머지는 여백이다.
그래서 **스틸샷(deviceScaleFactor 3 → 1170×2082)을 찍어 이어 붙이는** 쪽이 낫다.
UI 가 거의 정지 화면이라 결과물도 더 선명하다. 스크립트 패턴은 이 세션 기록 참고.

Mirr(mirra.my) MCP 로 **5개 플랫폼에 직접 발행**한다. 틱톡 공식 API 처럼
사용자가 위젯에서 제출 버튼을 눌러야 하는 구조가 아니다 — 에이전트가 올린다.

### 계정 ID

```
틱톡        f147c468-8120-4a11-8213-3df6dcf1db75   IMVOCA
인스타그램   1c6280a4-b48a-457c-8331-f6aab6b51fad   imvoca.app

유튜브       0728b5b5-2f9d-490f-a7c6-5e9e6c623eaa   IMVOCA

프로젝트     e909b18c-766c-4861-8343-83ab69637360   General
```

### ⚠️ 발행 확인 방법

`post_publish_now` 는 **접수**만 한다. `post_get` 으로 `status: published` 와
**외부 ID(socialPostId / sourceUrl)** 를 둘 다 확인해야 올라간 것이다.

외부 ID 없이 `published` 만 뜨는 경우가 자주 있다(`operationOutcome: unknown`).
**실제로는 올라가 있었다** — 스레드 1차가 그랬다. **재시도하면 중복 게시된다.**
몇 분 뒤 다시 읽거나 앱에서 눈으로 확인할 것.

### 코인(크레딧)

영상 생성(Video Lab)은 **생성 전 견적 + `approvedCredits` 승인**을 요구한다 = 코인을 쓴다.
카루셀·블로그 생성도 같은 계열로 보인다. 게시·예약·DM·분석은 플랜 등급으로 갈리는 듯하다
(`appliesToAllPosts` 가 Standard 이상 필요). **정확한 단가·잔액을 읽는 도구는 없다** —
mirra.my 결제 페이지에서 확인할 것.

→ **영상은 Mirr 로 만들지 않는다.** ffmpeg 로 실제 앱 화면을 찍어 붙이는 쪽이
코인도 안 들고 진짜 제품이 보여서 전환이 낫다. Mirr 은 발행·DM·분석에만 쓴다.
