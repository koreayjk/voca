# 터진 릴스 역설계 → 스타일카드 → 내 대본으로 재제작

출처: 사용자가 준 `Claude_reel_reverse_engineering.pdf` (Online_Techtree).
**우리 환경(클라우드 컨테이너 + 힉스필드)에 맞게 고쳐 적었다.** 원문 그대로가 아니다.

핵심은 하나다. **"왜 터졌는지 추측하지 말고, 터진 영상을 숫자로 분해해서
그 수치를 내 영상에 적용한다."** 훅·컷 템포·색감·애니메이션·자막·오디오·구성
7가지를 재현 가능한 숫자로 뽑아 `styles/*.md` 에 저장하고, 다음부터는
"○○ 스타일로 만들어줘" 한마디로 쓴다.

## ⚠️ 원문과 다른 점 두 가지 (중요)

### 1. Whisper 가 이 컨테이너에 없다

원문은 Whisper 로 타임코드 자막을 받으라고 한다. 확인해봤는데
`whisper` · `faster_whisper` 둘 다 설치돼 있지 않다.

**대신 힉스필드 `video_analysis_create`(mode `glance`)를 쓴다. 0.05크레딧이다.**
`media_import_url` 로 영상을 올린 뒤, "말한 내용을 타임코드와 함께 그대로
받아적고, 말이 안 되면 그렇다고 하라"고 물어보면 된다.
(2026-11-26 2번 영상 음성 검증에 실제로 써서 동작 확인함)

### 2. 남의 릴스를 내가 받아올 수 없다

틱톡·인스타는 봇 요청을 막는다 (실제로 인스타 429, 틱톡은 빈 셸만 반환).
플랫폼 약관상으로도 다운로드는 조심해야 한다 — 원문도 같은 경고를 한다.

**그래서 레퍼런스는 사용자가 직접 줘야 한다.** 둘 중 하나:

- **A안 (권장)** — 영상 파일(.mp4)을 대화창에 올린다. 그러면 아래 분해를 전부 자동으로 한다.
- **B안** — 장면 바뀔 때마다 캡처 8~12장(첫 3초는 촘촘하게) + 각 캡처의 초 + 자막 텍스트.
  수치 정확도는 떨어지지만 훅 유형·구성·자막 스타일은 잡아낼 수 있다.

분석이 끝나면 **받은 영상 파일은 지운다.** 스타일만 남기고 영상은 안 남긴다.

## 레퍼런스 고르는 기준 (원문 그대로)

| 기준 | 이유 |
|---|---|
| 계정 평균의 3배 이상 | 팔로워가 많아서가 아니라 **영상 자체가 터진 것**만 |
| 내 분야 · 세로 9:16 | 공부·학생·교육 계열. 그대로 옮겨 쓸 수 있어야 한다 |

| **3~5개를 같이** | 하나는 우연, 여러 개의 공통점이 진짜 공식 |

## 분해 — 컨테이너에서 실제로 되는 명령

ffmpeg · ImageMagick 둘 다 설치돼 있다. 아래는 2026-11-26 에 돌려서 확인한 것들이다.

```bash
# 장면 전환 지점 (컷 타임라인)
ffmpeg -v error -i REF.mp4 -vf "select='gt(scene,0.25)',metadata=print:file=-" \
  -an -f null - 2>/dev/null | grep -o 'pts_time:[0-9.]*'

# 컷 길이 통계 (평균 · 최단 · 최장)
# → 위 출력을 차분내서 평균을 낸다. 숏폼은 보통 0.8~1.5초가 빠른 축이다.

# 0.5초마다 프레임 뽑기 (원문 방식)
ffmpeg -v error -i REF.mp4 -vf fps=2,scale=240:-1 f_%03d.png

# 주요 색 5개 (HEX)
convert FRAME.png -resize 200x -colors 5 -unique-colors txt: | grep -o '#[0-9A-F]\{6\}'

# 밝기 · 대비
ffmpeg -v error -i REF.mp4 -vf "select='eq(n\,200)',signalstats,metadata=print:file=-" \
  -an -f null - 2>/dev/null | grep -E 'YAVG|YMIN|YMAX'

# 오디오 박자감 (1초 단위 RMS → 어디서 꽉 차는지)
ffmpeg -v error -i REF.mp4 -af "astats=metadata=1:reset=1,ametadata=print:\
key=lavfi.astats.Overall.RMS_level:file=-" -f null - 2>/dev/null | grep -o 'RMS_level=[-0-9.]*'
```

자막 위치·크기·색·한 줄 글자 수와 애니메이션(줌·팝업)은 **프레임을 직접 눈으로 보고**
적는다. 측정한 값은 숫자로, 눈으로 본 건 "추측"이라고 표시한다.

## 스타일카드 형식 — `styles/<이름>.md`

```
# 스타일카드: <이름>   (원본: 조회수 ___ · 길이 __초 · 계정 ___)
- 훅:        첫 3초에 무엇이 나오나 + 유형(질문형 / 결과 먼저 / 반전 / 숫자)
- 컷 템포:   평균 __초 · 가장 빠른 구간 __~__초는 __초 · 멈추는 구간
- 색감:      #______ ×5 · 밝기 YAVG __ · 대비 · 필터 느낌
- 애니메이션: 컷마다 줌 __배 · 텍스트 팝업 빈도 · 전환 종류
- 자막:      위치(y) · 크기 · 색 · 강조 방식 · 한 줄 최대 __자 · 등장 방식
- 오디오:    음악 분위기 · 박자감 · 효과음 위치 · 대사 유무
- 구성:      훅 __초 → 전개 __초 → 반전 __초 → CTA __초
- 터진 이유 가설 3개 (근거와 함께)
```

`styles/목록.md` 에 이름 · 원본 링크 · 한 줄 특징을 한 줄씩 추가한다.

## 재제작 — 우리 파이프라인에 어떻게 적용하나

여기가 원문과 가장 크게 갈리는 부분이다. 원문은 HyperFrames/Remotion 으로
컷을 짜는 전제인데, **우리는 `seedance_2_5` 로 20초를 한 번에 뽑는다.**
그래서 스타일카드 항목마다 적용 지점이 다르다.

| 스타일카드 항목 | 어디서 적용하나 | 비용 |
|---|---|---|
| **훅 (첫 3초)** | seedance 프롬프트의 SHOT 1 + 첫 자막 | 0 |
| **구성 (비트 타임라인)** | seedance 프롬프트의 SHOT 1~4 초 배분 | 0 |
| **컷 템포** | ① 프롬프트에 컷 수를 더 요구 ② **생성 후 ffmpeg 로 다시 자른다** | 0 |
| **자막** (위치·크기·색·글자수) | ffmpeg `drawtext` — 완전히 우리 통제 | 0 |
| **색감** | ffmpeg `eq` / `curves` 로 후보정 | 0 |
| **애니메이션** (줌·팝업) | ffmpeg `zoompan` + drawtext 등장 타이밍 | 0 |
| **오디오** | 음악 프롬프트 + 사이드체인 더킹 | 약 4 |

**거의 전부 후보정으로 공짜로 적용된다.** 재생성이 필요한 건 훅과 구성뿐이고,
그건 프롬프트만 바꾸면 되니 역시 추가 비용이 없다.

### 컷 템포를 후보정으로 올리는 법

seedance 20초는 컷이 느긋하게 나온다 (2026-11-26 2번 영상 실측: **평균 2.40초**).
스타일카드가 0.9초를 요구하면, 생성된 20초에서 **정지·늘어지는 구간을 잘라내고**
같은 샷 안에서 **크롭을 바꿔 인위적으로 컷을 만든다**:

```bash
# 같은 소스에서 와이드 / 클로즈업 두 버전을 만들어 번갈아 붙이면 컷이 2배가 된다
ffmpeg -i SRC.mp4 -vf "crop=iw*0.62:ih*0.62:(iw-ow)/2:ih*0.10,scale=720:1280" close.mp4
```

⚠️ 대사가 있는 구간은 자르면 싱크가 깨진다. **영상만 자르고 오디오는 원본을
통째로 다시 map 하되, 잘라낸 길이만큼 다른 데서 채워 전체 길이를 맞춘다.**
(2번 영상에서 실제로 쓴 방법 — `queue.md` 의 '드라마형 실제 제작 순서' 3번)

## ⚠️ 지킬 선

원문도 같은 말을 한다. **스타일은 참고, 영상은 내 것으로.**

- 원본의 **영상·음원·고유 문구를 그대로 쓰지 않는다.** 저작권·신고 문제가 된다.
- 가져오는 건 **훅 유형 · 템포 수치 · 색감 수치 · 구성 비율** 같은 '공식'뿐이다.
- 터진 이유는 스타일만이 아니다. 주제·타이밍·계정 신뢰도도 크다.
  같은 스타일이라도 **우리 주제(수능 영어 단어)와 맞아야** 효과가 난다.
